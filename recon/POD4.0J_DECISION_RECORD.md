## D4.7 — Public-repo-flip discipline doctrine

**Landed at this SEAL.** Documents the architect-authorization-gate-only execution boundary at the public-flip moment.

**The discipline:**

1. **One-way action acceptance.** GitHub Settings → Visibility → Public is irreversible at the platform level. Treat as permanent; rollback handled forward via `v1.0.1` patches, not "unship" attempts.
2. **Pre-flip checklist required.** `recon/PREFLIP_CHECKLIST.md` is the canonical pre-flip discipline. Architect verifies the checklist before executing any platform action.
3. **Explicit architect-authorization-gate-only execution.** Platform-side actions are architect-only:
   - GitHub Settings → Visibility → Public
   - Push `v1.0-ship` tag to remote
   - Upload `release/` contents to GitHub Releases page
   - Post drafts to HN / Reddit / Twitter
4. **No TB self-execution of platform actions.** TB-performed actions stop at the Pod 4.0.J SEAL commit + repo-local push to `origin/main`. TB does not push tags outside SEAL workflow, does not upload to Releases page, does not post to social platforms.
5. **Rollback by patch, not by retraction.** Once public, the substrate is the substrate; the manifesto is the manifesto; the demo video is the demo video. If a critical issue is found, the response is a `v1.0.1` follow-up release with the fix, preserving the V1.0 SHIP historical artifact.

**Why:** The public-flip moment is the architect's, not the assistant's. Automation should not be able to make this call. Codifying the architect-only boundary ensures the flip is deliberate and that every public claim is verifiable against a substrate-canon anchor before it goes live.
